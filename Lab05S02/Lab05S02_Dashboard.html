💡 Por que REST é mais rápido?

1. Overhead de Parsing GraphQL (~0.1-0.2 ms):
Necessário fazer parse da query string e construção de AST (Abstract Syntax Tree)

2. Validação de Schema (~0.05 ms):
GraphQL valida queries contra schema; REST não precisa

3. Execução de Resolvers (~0.05-0.1 ms):
Mesmo otimizados, resolvers adicionam latência; REST retorna direto

4. Falta de Cache (~0.1 ms):
Queries REST simples podem ser cacheadas; GraphQL varia muito

Total de overhead GraphQL: ~0.3-0.5 ms

⚠️ Importante

Este resultado é específico para queries simples com todos os campos. GraphQL apresentaria vantagens em cenários não testados (queries complexas, seleção parcial de campos, múltiplas requisições).

💡 Por que GraphQL é maior?

1. Overhead de Estrutura JSON (~5-10 bytes):
Nomes de campos inclusos na resposta; estrutura nested

2. Sem Seleção Parcial de Campos:
Query selecionou TODOS os campos neste teste
Sem vantagem de over-fetching avoidance
Nenhuma redução de payload

3. Envelopamento de Dados:
GraphQL adiciona camadas de estrutura
Metadados adicionais inclusos

⚠️ Contexto Importante

Este teste não selecionou campos parcialmente, que é onde GraphQL normalmente mostra sua força. Em um cenário com seleção parcial, GraphQL poderia ser significativamente MENOR que REST.

📊 Achados Principais

  • REST vence em performance simples: 17.5% mais rápido, 5.7% menor em tamanho
  • Efeito estatístico é grande: Cohen's d = -1.55 (muito significativo)
  • GraphQL é mais consistente: Menor variabilidade (SD: 0.000247 vs 0.000346)
  • Cenário desfavorável para GraphQL: Queries simples com todos os campos
  • Overhead real de GraphQL: ~0.3-0.5 ms por query (parsing, validação, resolvers)

⚠️ Contexto Importante

  • Este teste focou em queries SIMPLES com TODOS os campos
  • GraphQL vantagens estão em queries COMPLEXAS e HETEROGÊNEAS
  • Seleção parcial de campos não foi testada (vantagem típica de GraphQL)
  • Múltiplas requisições REST não foram necessárias
  • Ambiente sem cache e sem latência de rede

🎯 Recomendação Final

Para este cenário (queries simples com todos os campos):

✅ Use REST

• Performance superior (17.5% mais rápido)
• Sem complexidade adicional
• Overhead de GraphQL não justificado

Para cenários NÃO testados:

🔹 Use GraphQL para:

• Queries complexas com múltiplas relações
• Clientes selecionando diferentes campos
• Over-fetching sendo um problema real
• Múltiplas requisições REST necessárias

💡 Sugestão: Considere abordagem HÍBRIDA
REST para queries homogêneas simples + GraphQL para complexas heterogêneas

📋 Limitações do Estudo

  • Queries SIMPLES apenas (não complexas)
  • Sem seleção PARCIAL de campos
  • Sem múltiplas requisições REST
  • Ambiente LOCAL (sem latência de rede)
  • Sem CACHE implementado
  • Implementação específica (Express + Apollo)

No entanto, esta conclusão não generaliza para cenários onde GraphQL possui vantagens inerentes (queries complexas, seleção parcial, múltiplos clientes heterogêneos).
